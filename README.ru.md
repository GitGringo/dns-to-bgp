# dns-to-bgp

Маршрутизация трафика по **имени домена**, когда IP-адреса назначения заранее неизвестны.

Многие сервисы (CDN, банки, видеоплатформы) резолвятся в меняющиеся наборы IP-адресов, поэтому статический список маршрутов всегда неполон. dns-to-bgp следит за DNS-ответами, проходящими через резолвер [Unbound](https://nlnetlabs.nl/projects/unbound/). Для каждого ответа, подходящего под ваши списки доменов, он анонсирует полученные IP как хост-маршруты `/32` и `/128` по BGP в [BIRD](https://bird.network.cz/) на время жизни DNS TTL. Нижестоящие маршрутизаторы (например, MikroTik) могут направить именно этот трафик по выбранному пути (скажем, в туннель), не зная адресов заранее.

[English version](README.md)

```
 клиент ── DNS-запрос ──▶ Unbound ──▶ вышестоящий резолвер
                            │ (python-модуль)
                            │  подошедшие A/AAAA-ответы (UNIX-сокет, NDJSON)
                            ▼
                   unbound-route-state ── iBGP /32, /128 + community ──▶ BIRD ──▶ маршрутизаторы
                   (таблица маршрутов, снятие по TTL,
                    атрибуты по правилам)
```

## Компоненты

| Компонент | Язык | Роль |
|---|---|---|
| [`unbound-bgp-announcer`](unbound-bgp-announcer) | Python | Модуль, загружаемый в Unbound. Сопоставляет ответы со списками доменов с wildcard (перечитываются на лету) и передаёт события по UNIX-сокету. DNS не блокирует. |
| [`unbound-route-state`](unbound-route-state) | Go | Демон. Хранит таблицу живых IP, снимает их по DNS TTL, назначает BGP-атрибуты по правилам и анонсирует маршруты встроенным [GoBGP](https://github.com/osrg/gobgp). Включает инструмент `ctl`. |

## Возможности

- Списки доменов с wildcard лежат в каталоге, наполняются любым внешним процессом и подхватываются без рестарта Unbound.
- BGP-атрибуты по домену: community, large community, next hop (отдельно для IPv4 и IPv6), AS path, local preference, MED. Правила тоже перечитываются на лету.
- IPv4 и IPv6 в одной BGP-сессии; graceful restart и long-lived graceful restart.
- Опционально: держать маршрут, пока к его IP идёт трафик (через conntrack), и сбрасывать подходящие имена из кэша Unbound при старте или по команде.
- Интроспекция через `unbound-route-state ctl` (статистика, маршруты, правила, состояние BGP), текст или JSON.
- Компактно и аккуратно: один статический бинарник, ограниченные очереди и таблицы, логи с ограничением частоты, память — единицы-десятки МБ.

## Ограничения

- Демон стартует с пустой таблицей маршрутов (персистентности нет); чтобы пережить рестарт демона, используйте graceful restart в BIRD.
- Анонсируются только хост-маршруты (`/32`, `/128`).
- Только Linux (необязательный keepalive использует conntrack).
